# Contributing to Meletiq

Open an issue before proposing a major change. Keep pull requests focused, explain the user-visible effect, and include relevant validation. For projects with npm tooling, use the supported Node version and `npm ci`; run the repository's checks before opening a pull request.

Do not include secrets, private customer information, or proprietary source from other projects. A public repository does not by itself grant a software license. Check each repository's licensing status before reuse.
